# Топология 3 — резервирование шлюза (HSRP)

```
                 .2 [R1] Gi0/1 ==10.2.1.0/30== Gi0/0 \
[PC1]--[SW1]--+                                        [R3] Lo0 1.1.1.1  («интернет»)
                 .3 [R2] Gi0/1 ==10.2.2.0/30== Gi0/1 /
   192.168.10.0/24 (Gi0/0 обоих маршрутизаторов)
   виртуальный шлюз HSRP: 192.168.10.1
```

## Идея
У клиентов один шлюз — виртуальный адрес `192.168.10.1`. Его обслуживает активный маршрутизатор группы HSRP.
Если активный маршрутизатор или его uplink выходит из строя, шлюз «переезжает» на резервный — клиентам
ничего перенастраивать не нужно.

## Адресация

| Устройство | Интерфейс | Адрес | Роль |
|------------|-----------|-------|------|
| R1 | Gi0/0 | 192.168.10.2/24 | HSRP active (priority 110) |
| R1 | Gi0/1 | 10.2.1.1/30 | uplink к R3 |
| R2 | Gi0/0 | 192.168.10.3/24 | HSRP standby (priority 100) |
| R2 | Gi0/1 | 10.2.2.1/30 | uplink к R3 |
| R3 | Gi0/0 | 10.2.1.2/30 | линк к R1 |
| R3 | Gi0/1 | 10.2.2.2/30 | линк к R2 |
| R3 | Lo0 | 1.1.1.1/32 | имитация внешнего узла |
| HSRP | virtual IP | 192.168.10.1 | шлюз для клиентов |
| PC1 | NIC | 192.168.10.10/24, шлюз 192.168.10.1 | |

## Как это работает
- `standby 1 ip 192.168.10.1` — общий виртуальный адрес группы 1.
- `standby 1 priority 110` на R1 — выше 100 по умолчанию, поэтому R1 становится active.
- `standby 1 preempt` — R1 заберёт роль обратно после восстановления.
- `track 1 interface Gi0/1 line-protocol` + `standby 1 track 1 decrement 20` — при падении uplink приоритет R1 падает
  до 90 (< 100) и активным становится R2. Без tracking HSRP не заметит обрыв uplink, а клиенты останутся «за мёртвым» шлюзом.
- R3 знает обратные маршруты: основной через R1, резервный через R2 (административная дистанция 10 — «плавающий» маршрут).

Конфиги: [`r1.cfg`](../configs/topology3/r1.cfg), [`r2.cfg`](../configs/topology3/r2.cfg), [`r3.cfg`](../configs/topology3/r3.cfg).

> Команда `track` доступна не во всех версиях Packet Tracer. Если она не принимается, настройте топологию
> без tracking — тогда резервирование сработает только при отказе самого маршрутизатора.

## Проверка
```
R1# show standby brief
R2# show standby brief
PC1> ping 1.1.1.1
PC1> ping -t 1.1.1.1              # непрерывный ping для эксперимента
```
Ожидаемый результат: R1 — `Active`, R2 — `Standby`.

## Эксперимент
1. Запустите непрерывный ping с PC1 на `1.1.1.1`.
2. На R1 выполните `interface GigabitEthernet0/1` → `shutdown`.
3. В `show standby brief` на R2 роль меняется на `Active`; ping теряет 1–3 пакета и продолжается через R2.
4. Верните `no shutdown` — R1 снова становится active (благодаря `preempt`).

## Для самостоятельной работы
1. Что произойдёт без `preempt`, когда R1 вернётся в строй? Проверьте.
2. Настройте HSRP-аутентификацию (`standby 1 authentication md5 key-string …`).
3. Добавьте вторую группу HSRP для другой сети и распределите нагрузку: R1 active для группы 1, R2 — для группы 2.
