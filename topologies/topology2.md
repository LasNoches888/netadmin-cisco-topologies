# Топология 2 — статическая маршрутизация через транзитный маршрутизатор

```
[PC1]--[SW1]--Gi0/0--[R1]--Gi0/1 ==10.1.12.0/30== Gi0/0--[R2]--Gi0/1 ==10.1.23.0/30== Gi0/0--[R3]--Gi0/1--[SW3]--[PC3]
   192.168.10.0/24                                                                         192.168.30.0/24
```

## Идея
Три маршрутизатора в цепочке. Ни один не знает всех сетей автоматически, поэтому каждому нужно
явно указать маршруты до «чужих» сетей. Типичная ошибка — настроить маршрут в одну сторону:
ping уходит, а ответ не возвращается.

## Адресация

| Устройство | Интерфейс | Адрес | Подключено к |
|------------|-----------|-------|--------------|
| R1 | Gi0/0 | 192.168.10.1/24 | LAN1 (PC1) |
| R1 | Gi0/1 | 10.1.12.1/30 | R2 Gi0/0 |
| R2 | Gi0/0 | 10.1.12.2/30 | R1 Gi0/1 |
| R2 | Gi0/1 | 10.1.23.1/30 | R3 Gi0/0 |
| R3 | Gi0/0 | 10.1.23.2/30 | R2 Gi0/1 |
| R3 | Gi0/1 | 192.168.30.1/24 | LAN3 (PC3) |
| PC1 | NIC | 192.168.10.10/24, шлюз 192.168.10.1 | |
| PC3 | NIC | 192.168.30.10/24, шлюз 192.168.30.1 | |

## Таблица статических маршрутов

| На устройстве | Сеть назначения | Следующий узел |
|---------------|-----------------|----------------|
| R1 | 192.168.30.0/24 | 10.1.12.2 |
| R1 | 10.1.23.0/30 | 10.1.12.2 |
| R2 | 192.168.10.0/24 | 10.1.12.1 |
| R2 | 192.168.30.0/24 | 10.1.23.2 |
| R3 | 192.168.10.0/24 | 10.1.23.1 |
| R3 | 10.1.12.0/30 | 10.1.23.1 |

Конфиги: [`r1.cfg`](../configs/topology2/r1.cfg), [`r2.cfg`](../configs/topology2/r2.cfg), [`r3.cfg`](../configs/topology2/r3.cfg).

## Проверка
```
R1# show ip route static
PC1> ping 192.168.30.10
PC1> tracert 192.168.30.10        # 192.168.10.1 → 10.1.12.2 → 10.1.23.2 → цель
```

## Для самостоятельной работы
1. Замените три маршрута на R1 одним суммарным/дефолтным: `ip route 0.0.0.0 0.0.0.0 10.1.12.2`. Что изменилось в `show ip route`?
2. Удалите на R3 маршрут до `192.168.10.0/24` и найдите, на каком узле «обрывается» путь, с помощью `ping` и `tracert`.
3. Добавьте резервный канал и плавающий статический маршрут (`ip route … 10.1.12.2 200`).
