# Проверка топологий

Общий порядок: сначала интерфейсы, затем маршрутизация, затем сквозная связность.

## Любая топология

```
Rx# show ip interface brief         # все нужные интерфейсы up/up, адреса верные
Rx# show ip route                   # есть записи C и L для своих сетей
Rx# show running-config | section interface
```

## Топология 1 (OSPF)

| Что проверить | Команда | Ожидается |
|---------------|---------|-----------|
| Соседство | `show ip ospf neighbor` | один сосед в состоянии `FULL` |
| Маршрут до чужой LAN | `show ip route ospf` | запись `O 192.168.2.0/24` (на R1) |
| Связность | `ping 192.168.2.10` с PC1 | успешно |

## Топология 2 (статика)

| Что проверить | Команда | Ожидается |
|---------------|---------|-----------|
| Маршруты | `show ip route static` | две записи `S` на R1, R2 и R3 |
| Путь | `tracert 192.168.30.10` с PC1 | три хопа: 192.168.10.1, 10.1.12.2, 10.1.23.2 |
| Обратный путь | `ping 192.168.10.10` с PC3 | успешно (иначе нет обратного маршрута) |

## Топология 3 (HSRP)

| Что проверить | Команда | Ожидается |
|---------------|---------|-----------|
| Роли | `show standby brief` | R1 — `Active`, R2 — `Standby`, virtual IP 192.168.10.1 |
| Отслеживание uplink | `show track 1` (R1) | `Line protocol is Up` |
| Внешний узел | `ping 1.1.1.1` с PC1 | успешно |
| Отказоустойчивость | `shutdown` на Gi0/1 R1 | R2 становится `Active`, ping продолжается |

## Типичные причины «не пингуется»

1. Интерфейс в состоянии `administratively down` — забыт `no shutdown`.
2. На PC неверный шлюз или маска.
3. Нет обратного маршрута (особенно в топологиях со статикой).
4. Не совпадают маски на концах линка `/30`.
5. В OSPF не объявлена сеть в `network …` или интерфейс помечен `passive-interface`, хотя там есть сосед.
